Target and probe configuration

When to use this app

Use this tool for targets where standard monitoring is not enough: no ICMP response, filtered traceroute, or a need for RTT/loss/jitter/path details.

MTR protocol

TCP follows service-port behavior and is useful for cloud/SaaS edges. ICMP is classic ping-style MTR and uses no port. UDP can help test UDP paths but is commonly filtered.

Endpoint probe

Endpoint probe measures only the final resolved destination. It feeds endpoint RTT, loss, jitter, quality score, and alerts.

If ICMP is selected, no endpoint port is used. If TCP is selected, blank port means target default/service port.

TCP/TLS service ports

Use this for service reachability checks such as 443 or 443,3478. These are separate from MTR probe ports.

DSCP/TOS

Per-target DSCP marks synthetic probes where supported. The app maps TOS = DSCP << 2.

Thresholds

Per-target thresholds override global defaults for latency, jitter, loss, and path-change alerts.
